03

名词解释

设计系统 design system
把品牌的颜色、字体、间距、组件和使用规则写成一份可查、可复用的文档，团队照着做就不会各画各的。本仓库就是 jiojio 的这份文档。
设计令牌 design token
给每个设计决定起一个名字（例如 --accent 表示强调色）。改一处，所有用到它的地方一起变。
三层级联 primitive → semantic → component
原始值（fawn.400 = #A07E58）→ 语义名（accent）→ 组件取值（button.primary.bg）。组件只能取阶梯上的值，不自造中间色。
W3C DTCG Design Tokens Community Group
W3C 社区组定的令牌交换格式。Tokens tab 可把整套令牌导出成这种 JSON，或导出成普通 CSS 变量。
Paper / Bark canvas colors
亮色底 Paper #FAF8F2（暖米色）与暗色底 Bark #2D271C（暖棕黑）。系统从不使用纯白或纯黑做底。
Fawn 与 Ink accent rule
Fawn #A07E58 是唯一强调色，规则是「Fawn = 输出 / 交互」；Ink #16140F 表示「输入 / 事实」。
字标与印章 wordmark / seal
logo 由小写 jio 字标（EB Garamond 500）与圆角方块上的「吉」印章组成，颜色都绑在 --accent 上。
六条禁令 non-negotiables
无 emoji、无感叹号、logo 与排版无渐变、投影模糊不超过 16px、单界面不超过 3 种字重、永不禁用按钮。
Babel Standalone in-browser JSX
让浏览器直接编译 JSX，所以仓库没有构建步骤，但首次打开需要联网从 unpkg 加载 React 与 Babel。
历史重写 git filter-repo
改写仓库里已有的每一个 commit（这里是作者邮箱与文件里的 URL）。所有 commit SHA 因此改变，需要 force push。

05

逐项详解（四问）

F1设计系统本体：12 个 tabindex.html · logo-final.html · src/
修了什么入库设计系统本体。index.html 放 :root 与暗色令牌，src/app.jsx 的 TABS 定义 4 组 12 个 tab（Brand 01 到 02、Foundations 03 到 07、UI 08 到 10、UX 11 到 12），每个 tab 一个 jsx；logo-final.html 是独立的 logo 规范页。
为什么这样修单页交互 HTML + 浏览器内编译 JSX，没有 npm、没有构建，clone 下来 python3 -m http.server 即用。代价是首次加载依赖 unpkg 与 Google Fonts。
不修会怎样品牌规则只存在于设计者脑中与零散文件里。新协作者想知道「强调色什么时候能用」「按钮能不能置灰」只能去问人；各人自取颜色与字号，品牌在几个月内就会漂移。
delta确定性：12 个 tab 可经 index.html#brand 到 #a11y 直达。度量：本地起服务后逐个打开 12 个 hash，每页都能渲染且侧栏高亮对应项；设计系统本体合计 3,928 行（wc -l）。
F2公开版 READMEREADME.md · docs/screenshots/
修了什么README 从「Internal brand guideline」口径重写为面向公开读者：中英并排的设计语言摘要（Paper 与 Bark、一个强调色一条规则、三副字体、令牌、六条禁令）、11 张截图、12 个 tab 索引、品牌基础值表、文件地图。随后补了中文摘要独立成段、License 节。
为什么这样修转 public 之后 README 就是门面。设计语言用一页文字加截图讲清，比让访客自己点开 12 个 tab 更快；截图放 docs/screenshots/，README 用相对路径引用。
不修会怎样公开仓库首页是一份写着 Internal 的内部说明，里面还有 git init / git push 的维护步骤。访客在首屏看不出这是什么、好不好看，也看不到任何一张画面，大概率直接关掉。
delta确定性：README 首屏出现标题、定位、Quick start；截图 11 张（ls docs/screenshots | wc -l）。度量：发布后抽一个没见过本项目的人，看他只读首屏能否说出「这是 jiojio 的品牌与设计系统」。
F3页头编号与分组修正（7 页）src/{layout,icon,components,states,forms,motion,a11y}.jsx
修了什么7 个页面的 kicker 改成与侧栏一致：
Layout 05 · UI → 06 · Foundations
Icons 06 · UI → 07 · Foundations
Components 07 → 08 · States 08 → 09 · Forms 09 → 10
Motion 10 · Motion → 11 · UX
Accessibility 11 → 12
为什么这样修以 src/app.jsx 的 TABS（编号与分组的唯一来源）为准，只改 kicker 一行，不动页面内容，也不重排侧栏。
不修会怎样用户在页头读到「Components · 07 · UI」，回侧栏找 07 看到的是 Icons；按页头编号向别人转述或检索时，会指到错的 tab。Icons 与 Layout 的分组还被写成 UI，而侧栏把它们放在 Foundations。
delta确定性：12 个页头 kicker 与 TABS 的 num 和 group 一一对应（01 到 05 本来就对）。度量：grep -n 'kicker=' src/*.jsx 与 TABS 逐行对照。
F4logo 规范页死链logo-final.html
修了什么页首的返回链接从 logo-lab-v6.html（仓库里不存在）改为 index.html#logo，文案从「back to lab」改为「back to design system」。
为什么这样修规范页是定稿后对外展示的页面，返回目标应当是主系统的 Logo tab，而不是已经不存在的实验页。
不修会怎样访客在 logo 规范页点左上角返回，得到一个 404（GitHub 上是 Not Found，本地服务是 File not found），而且从这页没有别的路回到主系统。
delta确定性：仓库内不再引用 logo-lab-v6.html。度量：grep -rn logo-lab-v6 . 无输出；点击返回落在 Logo tab。
F5MIT 许可，品牌资产保留LICENSE · README.md
修了什么新增 LICENSE（MIT，21 行）；README 增加 License 节，明确写出 jiojio 名称、jio 字标、「吉」印章是品牌资产，不在许可范围内。
为什么这样修设计系统希望被参考与复用，所以代码与文档用最宽松的 MIT；但品牌标识不能因此被别人当成自己的 logo，所以单独声明保留。
不修会怎样公开仓库没有 LICENSE 时，法律默认是「保留所有权利」：别人想复制、修改、再分发都没有授权依据，想参考的人会绕开。反过来，只放 MIT 而不声明保留，字标与印章在字面上也被一并授权了。
delta确定性：GitHub 仓库侧栏识别出 MIT；README 有品牌资产保留声明。度量：发布后看仓库首页 License 徽标，以及 grep -n 品牌资产 README.md。
F6历史重写：清除个人邮箱与个人账号 URL全部 commit · force push
修了什么转 public 前做了逐文件加全历史的扫描：没有密钥、本机路径、真人信息，但发现两处。一是两个早期 commit 的作者邮箱是个人 Gmail，用 git filter-repo --mailmap 全史改为 GitHub noreply 地址；二是旧 README 里指向个人账号的 clone URL，用 --replace-text 在历史中替换为组织地址。随后 force push。
为什么这样修邮箱写在 commit 对象里，仓库一公开，任何人 clone 后 git log 即可读到，公开后再删文件也删不掉历史。唯一办法是在公开前重写。
不修会怎样个人邮箱永久留在公开历史里，每个 fork 与 clone 都带一份副本，会被爬虫收集用于垃圾邮件与社工；个人账号 URL 让公开仓库与个人身份可关联。公开之后再清，已经散出去的副本收不回。
delta确定性：历史里的作者与提交者邮箱只剩 noreply 地址。度量：git log --format='%ae%n%ce' | sort -u 只含 noreply 域名。遗留两项（见 08 段）：重写前的旧 SHA 仍可经 GitHub 按 URL 直接访问，需向 GitHub support 申请清除；账号未开启邮箱隐私，GitHub 服务端生成的 merge commit 会再次带出邮箱（已发生一次并已重写修掉）。

08

决策点

  • 向 GitHub support 申请清除旧 SHA 缓存：重写前的 commit SHA 仍能按 URL 访问，里面是旧邮箱与旧 URL。只有 jiojio 能以账号所有者身份提交申请。
  • 开启账号设置「Keep my email addresses private」：不开则 GitHub 服务端生成的 merge commit 会再次写入个人邮箱，每次都要再重写一次历史。
  • React development 版换 production 版：index.html 目前加载 react.development.js，体积大且带开发警告。换版需要同步更换 SRI 哈希，属于 index.html 的功能性改动，留给下一版。
  • logo-final.html 与主系统 logo 色值不一致：logo-final.html 写默认 --accent = #7A5E3E（Fawn Deep），主系统 --accent = #A07E58（Fawn）且 Logo tab 说明 logo 取该 token。需要 jiojio 定稿以哪个为准，再统一一边。
